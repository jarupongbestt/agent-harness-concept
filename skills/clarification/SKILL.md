# Clarification

Ask for clarification only when different answers would change scope, behavior,
platform mapping, permissions, model policy, or acceptance criteria.

- If the user has only a rough idea, help refine the goal and surface the few
  meaningful directions before turning it into requirements.
- Use a short interview: ask one focused question at a time, follow up only on
  answers that change the decision, and stop once the Ticket is plan-ready.
- First infer safe, reversible defaults from repository evidence.
- Ask concise questions with the decision and its consequence.
- Do not ask about details that can be discovered read-only.
- Interpret short affirmatives such as "Ok" using the preceding message and the
  conversation context, rather than treating every affirmative the same way.
  After a factual explanation, it is an acknowledgement and authorizes no edits.
  After a concrete actionable proposal, it selects the approach; advance necessary
  authorized Intake and Planning, but wait for complete Plan approval before edits.
  After an actual approval request for a presented complete Plan, it is explicit
  approval; proceed within that Plan without asking again. A casual acknowledgement
  alone is not Plan approval or authorization for external mutation.
- Record the answer as an explicit requirement or assumption.

Before Intake, distinguish ordinary questions, explanations, discussion, and
status requests from execution by meaning and context, not punctuation. Answer
ordinary conversation directly; minimal read-only lookup does not create a new
run, Ticket, Plan, specialist invocation, or full lifecycle. Clear action questions
such as "can you fix this?" and substantial explicitly requested audits or research
route to execution. While authorized work is active, answer questions and resume
the same run with its artifacts; a question alone does not cancel or restart work
or justify stage re-entry. Changed requirements follow exact existing triggers,
recorded evidence, and renewed approval for material Plan changes.

If ambiguity is non-material, proceed and state the assumption.
