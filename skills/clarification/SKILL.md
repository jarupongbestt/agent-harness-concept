# Clarification

Ask for clarification only when different answers would change scope, behavior,
platform mapping, permissions, model policy, or acceptance criteria.

- If the user has only a rough idea, help refine the goal and surface the few
  meaningful directions before turning it into requirements.
- Use a short interview: ask one focused question at a time, follow up only on
  answers that change the decision, and stop once the Ticket is plan-ready.
- First infer safe, reversible defaults from repository evidence.
- Ask concise questions with the decision and its consequence.
- Do not ask about details that can be discovered read-only.
- Do not treat a casual acknowledgement as approval for a plan or external
  mutation.
- Record the answer as an explicit requirement or assumption.

If ambiguity is non-material, proceed and state the assumption.
