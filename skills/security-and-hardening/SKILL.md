# Security and Hardening

Apply this skill when a change handles secrets, credentials, user data, external
input, permissions, code execution, network access, or destructive operations.

- Identify trust boundaries and validate untrusted input at the boundary.
- Apply least privilege to tools, files, agents, and external actions.
- Do not expose secrets in logs, artifacts, prompts, or error messages.
- Preserve safe failure behavior and explicit approval for irreversible actions.
- Check dependency, path, command, and serialization risks relevant to the task.
- Report residual risk and the exact evidence supporting the conclusion.

Do not invent a vulnerability without a plausible attack path or direct evidence.
