# Test-Driven Development

Treat acceptance criteria as the definition of correct behavior.

- Design tests independently of the Implementer's internal approach.
- Cover the normal path, important boundaries, invalid input, and relevant error
  behavior.
- Reproduce a bug before changing code when feasible, then keep a regression test.
- Use existing regression coverage for refactors and avoid tautological tests.
- Report unavailable checks honestly; absence of a test is not a passing result.
